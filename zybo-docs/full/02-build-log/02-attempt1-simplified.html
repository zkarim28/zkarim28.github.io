Attempt 1 · simplified HDMI-out-only design (09-18 → 09-21)

IP on a hand-simplified block design at 0x43C10000. Ended with no output and was abandoned.

02.1Attempt 1: what was wrong with the platform

What I did
  • The Vitis project pointed at an XSA dated 2024-07-04 with no Lorenz IP. The newly exported XSA (lorenz_ivan_9_18.xsa) had the IP at 0x43C10000 but no RX blocks (no v_tc_in, no axi_gpio_video, no dvi2rgb).
  • The stock video_demo.c uses XPAR_V_TC_IN_*, XPAR_AXI_GPIO_VIDEO_* and video_capture, so it could not compile against that platform.
Why

This is why the simplified design needed a cut-down demo and a rebuilt platform.

Related: Issue I-06

02.2Attempt 1: found the solver could never leave zero

What I did
  • Reading the RTL before writing PS code showed the integrators load InitialOut only while reset is high; during reset the AXI registers are 0, so the state seeds to (0,0,0) — a fixed point of the Lorenz equations.
  • Added load = CTRL bit 1: slv_reg_ctrl[1] → lorenz_dda_driver.v → lorenz_solver.v → each integrator (reset | load reloads init). Top-level ports did not change, so component.xml needed no edit.
Why

Without it, no software could ever start the solver.

Code · integrator.v — accumulator with software load (Verilog)
ivan_lorenz_hdmi/Zybo-Z7-HW/ip_repo/lorenz_dda_driver_1_0/src/integrator.v
`timescale 1ns / 1ps

module integrator
(
input                   clk,
input                   reset,
input                   load,        // reload InitialOut without a global reset (software controlled)
input                   enable,      // pulse high for one cycle to take a single integration step
input signed [26:0]     funct,      //the dV/dt function
input signed [26:0]     InitialOut,  //the initial state variable V

output signed [26:0]    out //the state variable V
);

    reg  signed [26:0] v1 ;
    wire signed [26:0] v1new ;
    wire signed [26:0]  adder_out;

    always @(posedge clk) begin
        v1 <= v1new;
    end

    assign adder_out = v1 + funct;   // Adder
    assign v1new = (reset | load) ? InitialOut : (enable ? adder_out : v1); 

    assign out = v1; // Assign output

endmodule
Note

Edited untested in simulation; it worked on hardware in attempt 3.

02.4Attempt 1: platform and app

What I did
  • Update Hardware Specification with lorenz_hdmi.xsa; platform build failed on the driver Makefile (I-07) and was fixed in six copies.
  • App cut down to the HDMI-out path (capture, interrupts, menu items 5-8 removed); src/video_capture deleted because it needs xgpio. All files compiled with the ARM compiler against the new xparameters.h.
  • Launch-config bitstream name was stale (design_1_wrapper.bit vs lorenz_hdmi.bit) and fixed.
Why

Removing the RX code was the price of the simplified PL.

02.5Attempt 1: no UART output, no HDMI signal — abandoned

What I did
  • Board programmed and app launched: nothing on the terminal and 'no signal' on the monitor.
  • Checks: TX pins/TMDS_33 in the XDC were right; PS UART1 on MIO 48-49 and STDOUT 0xE0001000 were right; the ELF was older than the latest edits; boot markers [1]-[5] were added; debugger 'Suspend' inspection was suggested.
  • The cause was never found. Decision: throw the simplified design away and restart from a fresh Digilent project.
Why

A stock, known-good design was cheaper than debugging a hand-modified one.
