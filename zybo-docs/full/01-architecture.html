01 · Architecture

The stock Digilent demo, what I added, and how data flows.

0. Three attempts, one final design

  • Attempt 1 (hdmi_driver): RX path removed from the block design, IP at 0x43C10000, demo cut down. Never produced output.
  • Attempt 2 (fresh Digilent project): full stock design + IP at 0x43C30000, first PS plotter (lorenz_plot.c, l key).
  • Attempt 3 (fresh again): the design described below. Everything else on this page is the attempt-3 design.

1. What the original Digilent demo does

  • PL: PS7 (GP0 for control, HP0 for video DMA); axi_dynclk generates the pixel clock; axi_vdma reads frame buffers from DDR into an AXI-Stream; v_axi4s_vid_out + v_tc_out (timing) → rgb2dvi → HDMI TX. An RX chain (dvi2rgb, v_tc_in, v_vid_in_axi4s, axi_gpio_video) writes captured video back to DDR.
  • PS: video_demo.c runs a UART menu: change resolution, pick a frame buffer, test patterns, capture / invert / scale the HDMI input. Drivers: display_ctrl, dynclk, video_capture, intc, timer_ps.

3. Data flow

Highlighted boxes are new. Control path: PS → GP0 → interconnect → Lorenz IP (write parameters, pulse step, read x/y/z). Video path: the CPU draws into DDR; the VDMA streams it through the stock Digilent TX chain to HDMI. The PL only computes numbers; the CPU draws the picture.

  • Control path: PS Xil_Out32/Xil_In32 → GP0 → axi_interconnect_gp0 → M05_AXI → lorenz_dda_driver_0. Software writes parameters, pulses load, then pulses step and reads X/Y/Z back.
  • Video path: CPU writes pixels (3 bytes, R,B,G) into a DDR frame buffer → D-cache flush → axi_vdma (MM2S over HP0) → v_axi4s_vid_out with v_tc_out timing → rgb2dvi → HDMI TX; axi_dynclk sets the pixel clock (148.5 MHz for 1080p60 in the stock driver).
  • The PL never touches the pixels; the plot is 100 % software.

4. The Lorenz core

  • Equations: dx = σ(y − x), dy = x(ρ − z) − y, dz = xy − βz. Euler with step 2−dt, implemented by right-shifting the operands by dt.
  • Number format: 27-bit signed, 1 sign + 6 integer + 20 fractional bits ("Q6.20"), value = raw / 220, range about ±64.
  • signed_mult multiplies two 27-bit values and keeps {sign, product[45:20]}; integrator is v ← v + funct on a step pulse and reloads init on reset | load.
  • lorenz_solver turns CTRL bit 0 into a one-clock step on its rising edge and drives done one clock later.
