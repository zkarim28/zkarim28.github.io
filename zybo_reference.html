Zybo-Z7 Quick Reference — Best Practices

Fast lookup for the recurring Vivado/Vitis workflows on the Zybo Z7-10: opening projects, packaging a new AXI4 IP, wiring it into a block diagram, generating a bitstream, and exporting/importing hardware into Vitis to read the new IP's registers.

Vivado

Everything from opening the project through exporting the hardware platform (.xsa) for Vitis.

Best Practices

Opening a Previous Project

Open "Vivado 2024.1" from your Xilinx Design Tools.

Click "Open Project", or pick one directly from "Recent Projects."

If you selected "Open Project," navigate through your HW (hardware) folder to find the .xpr project file.

You are brought to the "Project Manager" page.

Typically, click "Open Block Design" found under "IP INTEGRATOR" in the Flow Navigator sidebar.

Your previous block diagram opens up. To view the whole thing, click the "Zoom Fit" button or use Ctrl+0.

To find your Verilog, block diagram, and wrapper files, click on "Sources" in the top-left window of the Project Manager.
Best Practices

Creating a New IP

In Vivado, navigate to Tools and select "Create and Package New IP" in the dropdown.

You'll be brought to the IP popup window. Click "Next."

Select "Create a new AXI4 peripheral," then press "Next."

Type in a name for your block in the "Name:" field. If you don't have an "IP Location" already, Vivado automatically creates an ip_repo for you. Click "Next."

Your ip_repo is typically found in your hardware folder, but you can always point it to a different location.

Edit your interface parameters as needed. Click "Next."

Select "Edit IP" to be taken immediately to the new hardware project containing your IP. Click "Finish."

In the same Vivado window you're redirected to the IP's own "Project Manager" — the "Package IP" view.

Double-click {ip_name}.v in the "Sources" window and also {ip_name}_slave_lite_v1_0_S00_AXI.v. Observe their contents:

  • {ip_name}.v contains the direct connection to the AXI bus.
  • {ip_name}_slave_lite_v1_0_S00_AXI.v contains a handshake FSM to interface with the AXI bus protocol.

In this tutorial, we create a down counter — go to the "...slave..." Verilog file and implement your logic to be written out to the AXI data output.

Leave slv_reg1, slv_reg2, slv_reg3 in place to stay 0. Only slv_reg0 was replaced with a register named count_value.

Great, our work here is done. In this Vivado window (or a new one), go File → Project → Open or Open Recent to return to the main project. If prompted, click "Yes" to open the next project.

Best Practices

Adding New IPs / Our Own Verilog Modules

In your main project, navigate at the top to Tools → Settings (gear icon).

In the Settings popup, navigate to the "IP" dropdown → "Repository."

Click the plus icon. In the file explorer, find the folder named {ip_name}_{version_number} (e.g. down_counter_1_0). It's always great to click "Refresh All."

If you've already pointed to the ip_repo in this project, the new IP may have been picked up already!

Click "Apply," then click "OK."

Best Practices

Adding IP/Module to Block Diagram

Right-click anywhere on the block diagram. Click "Add IP..." in the menu.

Type in your IP's name.

You'll now see your IP! A green bar appears at the top of the "Diagram" tab. Click "Run Connection Automation" to wire the pins.

If your AXI bus doesn't have enough ports to connect your peripheral, that's okay — "Run Connection Automation" will create a new Master port, clock, and reset for the peripheral.

In the "Run Connection Automation" popup, make sure all checkboxes for the IP are checked, then click "OK."

You'll notice the AXI bus has expanded. Click "Regenerate Layout" to make the connections easier to see.

Best Practices

Generating Bitstream

Automatically runs Linting, Synthesis, Implementation, and Place and Route.

We now have the IP connected into our system.

Right-click anywhere in the block diagram whitespace and select "Validate Design." Hopefully you don't have any errors — you're now ready to Generate Bitstream.

At the bottom left, in the Flow Navigator, click "Generate Bitstream" under the "PROGRAM AND DEBUG" dropdown.

If prompted, click "Save." Then click "Yes" to launch synthesis and implementation first. Edit the number of jobs as your machine's resources allow.

To track progress, find the "Design Runs" tab in the bottom window below the block Diagram window.

Synthesis becomes especially fast when previously run — Vivado caches synthesis of all other IP blocks in the diagram. New blocks take time to synthesize. A design not meeting timing isn't always bad, depending on context, especially for a huge project.

When fully complete, you'll see this popup window. Select whichever option and click "OK."

You might not always see "Open Implemented Design."
Best Practices

Exporting Hardware

Navigate to File → Export → Export Hardware. Click "Next."

Select "Include Bitstream."

What is a bitstream? It's exactly how we configure the logic on the FPGA to make the hardware happen!

Name it whatever you want. Click "Next," then "Finish."

Vitis

Bringing the exported hardware into Vitis Classic and reading your new IP's registers from C.

Best Practices

Opening Previous Projects

Open Vitis. Navigate to the appropriate workspace.

If you forgot what the workspace folder looks like inside, here's an example. Click "Launch." Then click "Continue With classic Vitis."

Best Practices

Importing Vivado Hardware Files to Vitis

You're opened up to the Vitis workspace.

Find the green icon — here it's named design_1_wrapper. Right-click on it. Select "Update Hardware Specification."

Click "Browse." Find your .xsa file with the name you provided when you last exported your hardware. Then click "Ok."

A popup notifies you the hardware specification has been updated. Click "OK." You'll notice your hardware is now (Out-of-date).

This is okay — it's fixed when we build the project. You must build to load in a MACRO to easily access your new AXI address.

Navigate to the Assistant bottom-left window. Right-click "Debug" within the [Application] and click "Build."

Best Practices

Accessing AXI Addresses

You must build to load in a MACRO to easily access your new AXI address.

In the same "Explorer" tab, open the dropdown for the hardware. Double-click platform.spr.

On the bottom left of this window, click on "Hardware Specification."

It may look a little different depending on your Vitis version.

On the "Hardware Specification" page, scroll down to see your IP's new address in the Address Map table.

Best Practices

Reading Data from New IPs/AXI Peripherals

A more organized way: create a new folder in the src folder. Right-click src → New → Folder. Name it after your IP or AXI peripheral.

In your new folder, right-click → New → File. Name it {ip_name}.h. Repeat for a .c file.

In the .h file, here's an example of contents:

#ifndef DOWN_COUNTER_H_
#define DOWN_COUNTER_H_

#include "xil_types.h"

/*
 * Reads register 0 of the down_counter AXI4-Lite IP: a value that
 * decrements on its own inside the FPGA fabric, once per AXI clock,
 * from 1000 down to 0 (see count_value in
 * down_counter_slave_lite_v1_0_S00_AXI.v).
 */
u32 DownCounter_Read(u32 baseAddr);

#endif /* DOWN_COUNTER_H_ */

In the .c file, here's an example of contents:

#include "down_counter.h"
#include "xil_io.h"

#define DOWN_COUNTER_REG0_OFFSET 0x0

u32 DownCounter_Read(u32 baseAddr)
{
    return Xil_In32(baseAddr + DOWN_COUNTER_REG0_OFFSET);
}

Somewhere at the top of your main C file you'll want to add this line:

#define DOWN_COUNTER_BASEADDR XPAR_DOWN_COUNTER_0_S00_AXI_BASEADDR

You can verify the address macro is proper by finding xparameters.h in the right-hand "Outline" column and double-clicking it.

Search for your IP — it may look like this:

If you can't find it, cancel out of the tab, build the project, and open it again.

Example use of the code to read and print to the serial:

u32 countVal = DownCounter_Read(DOWN_COUNTER_BASEADDR);
xil_printf("down_counter = %lu\n\r", (unsigned long) countVal);
