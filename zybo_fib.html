How to Setup

Open Vivado

Create Project

Vivado projects are opened inside vivado and are of type .xpr.

To make a "block diagram only" project, check the box "Do not specify sources at this time."

On the top left, navigate to the Boards tab, then type zybo in the search bar to find the Zybo Z7-10. (If not found, click the refresh button on the bottom left.) Click the download button under the "Status" column. Once complete, click into the Display Name box of the "Zybo Z7-10" row to select it, then proceed.

Click Finish (the extra settings like "Speed Grade" have already been completed for you).

My First Block Diagram

    Block design flow
  • 1 Instantiate and configure IP blocks
  • 2 Create connections between ports
  • 3 Generate bitstream (run Synthesis if prompted)
  • 4 Export hardware -> transferring .xsa to Vitis

You are currently on the main page:

Click on "Create Block Design." Type in a name, then click OK.

You will automatically open up to the Diagram page.

Click on either "Plus" button to open the IP menu. In the search bar, type zynq and double-click "ZYNQ7 Processing System."

To determine the clock frequency sent from the PS to the PL fabric, double-click the ZYNQ7 Processing System, navigate to Clock Configuration, then find the PL Fabric Clock dropdown.

Now for the AXI bus: every slave and master on the AXI can have its own clock and reset. The slave connects to the master; clock-domain crossing is handled for you. Here, we supply the same clock to both.

At this point, the "Processor System Reset" and an "AXI Interconnect" have been added, without editing their internal settings.

Can drag a net and let go in free space to keep that selected so you can connect it to multiple ports.

Adding GPIOs is easy! Go to the Board tab on the top left, double-click "4 LEDs," and click OK in the "Connect Board Component" popup.

The GPIO component and ports have been added.

Hook up the clock, reset, and AXI.

Click the "Regenerate Layout" button to make it look pretty.

Add the following blocks to the diagram: "Block Memory Generator" and "AXI BRAM Controller."

Double-click into the "AXI BRAM Controller" and edit the "Number of BRAM interfaces" to 1:

Connect the AXI, ZYNQ clock and interconnect reset, and BRAM port.

After a "Regenerate," we have the following.

Processor can use the interface to access LEDs and memory. GPIO converts AXI register space into inputs and outputs. On output, when the processor writes a value to that AXI address, the register write drives the outputs — so 1111 in binary drives all 4 LEDs.

To also accept switch input on the GPIO: double-click into the "AXI GPIO," navigate to "IP Configuration," then check "Enable Dual Channel" and "All Inputs."

Go to the Board tab (top left) and double-click "4 Switches" under GPIO. Vivado will automatically detect the new GPIO port and select it.

Here is the final block diagram!

Why use block memory instead of the processor's own memory? If you have a module or algorithm, block memory is easier to access and saves the CPU's memory for CPU tasks. The CPU can write to memory at a specific address, and read back from that same address later.

Assign Addresses for the AXI Bus

Navigate to the "Address Editor" tab on the right side window. Expand all if you'd like. Right-click in the window and select "Assign All."

The base address is used by the CPU to address a peripheral via the bus. Why a high address too? Each peripheral gets a range of addresses.

In the "Range" column, I clicked the GPIO's dropdown (showing "64") and decreased the range down to 4K — we don't need that much range for simple LEDs.

In block RAM, every byte has an address. So for a 32-bit address, you increment by 4 to get the next 32-bit word.

Generate Bitstream

You need a top-level HDL file — so far we just have a diagram. Navigate to the "Sources" tab on the top left and right-click the yellow block-design entry.

Click "Ok" on the popup. You should now see a "wrapper" in bold text under the "Sources" tab.

You can even double-click the wrapper to view the top-level Verilog code!

On the bottom left, click "Generate Bitstream" and click "Save" in the popup.

Click "Yes" in the next popup window.

Click "Ok" on the next window.

Please wait (12:11 AM → 12:...)

Simply hit "Ok."

You will then see the chip/fabric view:

Go File → Export Hardware, Next. Then check "Include bitstream," Next, Finish.

This creates a wrapped-up file to use in Vitis — bitstream included, so you can program the FPGA from Vitis!

Vivado exported hardware are of type .xsa. These are used in Vitis to build software applications off of the hardware.
Dont name everything the default "design_1_wrapper" name because multiple projects having this can cause errors. If you get a domain error when creating Vitis project, try re-exporting the hardware.

Vitis — Interfacing from the PS Side

At the top of Vivado, go to Tools → Launch Vitis IDE.

Once open, click "Open Workspace."

Create a new folder to be your workspace and click OK.

At this point I switched to Vitis Classic (the Unified IDE is newer, and worth learning separately — it's deprecated).

Click "Create application project."

Navigate to the "Create a new platform from hardware (XSA)" tab, then Browse.

Navigate to the .xsa file we generated earlier.

When I tried this in the Unified IDE, a missing-tool issue came up. Running sudo dnf install xlsclients fixed it.

The "Platform name" should auto-populate. Click Next.

The platform project is done — moving on to the "App" of the System Project. Type in a name for the Application project, then click Next.

After the "App" is made, move on to the "Domain." Keep all settings the same. Click Finish.

The wrapper contains the exported hardware, while the system has the c application and source code for the processor side.

Combining Your Own HDL

▶ Zynq Part 3Combining my own HDL with the Vivado block diagram

Revisit the diagram. Right-click on only the small port of the processor clock, then click "Create Port."

Leave it as output.

Do the same for the peripheral_aresetn[0:0] pin on the "Processor System Reset" module.

Double-click the "Block Memory Generator." Change the "Memory Type" to "True Dual Port RAM."

We'll add an extra port on the BRAM, accessed by both the PS and our own hardware. Every byte in this RAM has a different address — the bottom two bits are the byte address within the word. Important to know, since normally an address refers to an entire word.

Right-click on the new port and select "Make External."

Click the plus under "Sources."

Add in the files from this repo:

🐙 HDLForBeginners/Examplesgithub.com — ZynqSeries folder

There's a new top level now. The source folder should update its hierarchy — create the HDL wrapper again.

Generate the bitstream again (this takes some time). Once complete, export hardware again — it will have a new name, zynq_example_top.

Back in Vitis, right-click zynq_example_wrapper in the explorer and click "Update Hardware Specification."

Browse to find the latest hardware we just exported.

It will say "out of date" — just build the project again.
